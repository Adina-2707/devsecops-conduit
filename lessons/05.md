# Lesson 05 · Automation: from typed commands to a script, then to Ansible

By the end of the lesson:

- you released once more by hand and counted the commands;
- the same release is one script;
- you saw where a script stops being enough;
- the whole server is an Ansible playbook that you can run any number of times.

You work on the laptop and on your server from Lesson 4, where the complete Conduit runs at `https://YOUR-NAME`. In the commands, replace `YOUR-IP` with the address of your server, `YOUR-NAME` with your domain name and `<you>` with your GitHub username.

## Starting state

- `https://YOUR-NAME` shows your Conduit (Lesson 4).
- On the laptop, your clone is in `~/devsecops-conduit` and `git pull` on `main` works.

## Mission 1 · A release by hand, once more (20 minutes)

**1. Make version 0.3.0** on the laptop. It teaches the health check to report which commit is running.

```bash
cd ~/devsecops-conduit
git switch main
git pull
git switch -c release/0.3.0
```

Make `backend/version.py` look like this:

```python
import os

__status__ = True
__version__ = "0.3.0"
__message__ = "Conduit Realworld API"
__revision__ = os.getenv("APP_REVISION", "unknown")

response = {"success": __status__, "version": __version__, "message": __message__, "revision": __revision__}
```

```bash
git add backend/version.py
git commit -m "Release 0.3.0: the health check reports the revision"
git push -u origin release/0.3.0
```

Open a pull request **into your own fork** and merge it.

**2. Release it by hand.** Log in to the server and type the release, one command at a time. Count them:

```bash
ssh azureuser@YOUR-IP
cd /opt/conduit/src
sudo git pull
sudo /opt/conduit/venv/bin/pip install -r backend/requirements.txt
cd frontend
sudo npm install --no-package-lock
sudo npm run build
sudo systemctl restart conduit conduit-web
curl localhost:8000/api/health-check
```

Checkpoint: `"version":"0.3.0"` and `"revision":"unknown"`. Nobody told the application which commit it is.

> [!NOTE]
> Eight commands, in this order, every time. Skip `npm run build` and visitors get the old pages with the new API. Skip `restart` and nothing changes at all. And the server cannot even say which commit it runs.

Leave the server with `exit`.

## Mission 2 · The same as a script (25 minutes)

**1. A branch** on the laptop:

```bash
git switch main
git pull
git switch -c release/script
```

**2. Write the commands down.** Create `scripts/release.sh`:

```bash
#!/usr/bin/env bash
# Release the newest main on this server. Run it as root.
set -euo pipefail

cd /opt/conduit/src
git pull

/opt/conduit/venv/bin/pip install -q -r backend/requirements.txt

cd frontend
npm install --no-package-lock
npm run build

systemctl restart conduit conduit-web
sleep 5

curl -fsS http://127.0.0.1:8000/api/health-check
echo
curl -fsS -o /dev/null http://127.0.0.1:3000
echo "OK: released $(git rev-parse --short HEAD)"
```

These are your eight commands. Three things are new. `set -euo pipefail` stops the script at the first command that fails. `curl -f` fails when the answer is an error, so a broken release ends with an error instead of `OK`. The last line prints which commit was released.

**3. Give the release something to release.** In `backend/version.py` change `0.3.0` to `0.3.1`. Then:

```bash
git add scripts/release.sh backend/version.py
git commit -m "Release 0.3.1 with a release script"
git push -u origin release/script
```

Open a pull request into your own fork, merge it, and update the laptop:

```bash
git switch main
git pull
```

**4. Release with one command** from the laptop:

```bash
ssh azureuser@YOUR-IP 'sudo bash -s' < scripts/release.sh
```

Checkpoint: the last two lines show `"version":"0.3.1"` and `OK: released` with a commit.

> [!NOTE]
> The script is the same every time, for everybody. It went through a pull request, so somebody else read it. A classmate can release your project tonight without knowing the eight commands. `sudo bash -s` runs the script from your laptop on the server, so there is nothing to copy first.

## Mission 3 · Where the script ends (25 minutes)

**1. Run it again**, although nothing changed:

```bash
ssh azureuser@YOUR-IP 'sudo bash -s' < scripts/release.sh
```

It takes just as long. It installed, built and restarted everything again, and your site was down for a few seconds for no reason. The script does not know that nothing changed.

**2. Ask the script to set up the server too.** A release script is not enough for a new server: there is no user, no database, no folder. Try one setup step in a tiny script:

```bash
ssh azureuser@YOUR-IP 'sudo bash -s' <<'EOF'
set -euo pipefail
useradd --system --shell /usr/sbin/nologin conduit
echo "this line is never reached"
EOF
```

Checkpoint: `useradd: user 'conduit' already exists`, and nothing after it runs.

**3. Make it safe to run twice.** Every step needs a question in front: is it done already?

```bash
ssh azureuser@YOUR-IP 'sudo bash -s' <<'EOF'
set -euo pipefail
id conduit >/dev/null 2>&1 || useradd --system --shell /usr/sbin/nologin conduit
sudo -u postgres psql -tAc "SELECT 1 FROM pg_roles WHERE rolname='conduit'" | grep -q 1 || sudo -u postgres psql -c "CREATE USER conduit"
[ -d /opt/conduit ] || mkdir /opt/conduit
echo "three steps, three different ways to ask: is it already done?"
EOF
```

Checkpoint: it runs to the end, twice if you like.

> [!NOTE]
> Three steps needed three different checks, and you had to know each one. Lessons 3 and 4 have about forty steps: packages, a user, files with secrets, a database, services, a web server. Somebody already wrote and tested the right check for each kind of thing. That is what Ansible is.

## Mission 4 · The whole server as a playbook (50 minutes)

Everything in this mission happens on the laptop, in `~/devsecops-conduit`.

**1. A branch, and Ansible:**

```bash
git switch main
git pull
git switch -c deploy/ansible
source .venv/bin/activate
python -m pip install ansible-core
ansible-galaxy collection install community.postgresql
mkdir deploy
```

**2. The inventory: which server.** Create `deploy/inventory.ini`:

```ini
[conduit]
server ansible_host=YOUR-IP ansible_user=azureuser

[conduit:vars]
repo_url=https://github.com/<you>/devsecops-conduit.git
site_name=YOUR-NAME
ansible_ssh_common_args=-o UserKnownHostsFile=deploy/known_hosts -o StrictHostKeyChecking=yes
```

**3. Pin the identity of your server.** Save its public host key in the repository, then compare the fingerprint with the one the server reports itself:

```bash
ssh-keyscan -t ed25519 YOUR-IP > deploy/known_hosts
ssh-keygen -lf deploy/known_hosts
ssh azureuser@YOUR-IP ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Checkpoint: both lines show the same `SHA256:…`.

> [!NOTE]
> Your key proves to the server who you are. The host key proves to you which server it is. With the fingerprint saved in the repository, Ansible refuses to talk to any machine that only pretends to be your server. Next lesson a robot uses the same file.

**4. The three files you wrote by hand, as templates.** The parts in `{{ }}` are filled in by Ansible.

`deploy/conduit.service.j2` — the unit from Lesson 3, with one new line that tells the API which commit it is:

```ini
[Unit]
Description=Conduit API
After=network.target postgresql.service

[Service]
User=conduit
WorkingDirectory=/opt/conduit/src/backend
EnvironmentFile=/etc/conduit/conduit.env
Environment=APP_REVISION={{ code.after }}
ExecStartPre=/opt/conduit/venv/bin/python -m alembic -c alembic.ini upgrade head
ExecStart=/opt/conduit/venv/bin/uvicorn conduit.app:app --host 127.0.0.1 --port 8000
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

`deploy/conduit-web.service.j2` — the unit from Lesson 4:

```ini
[Unit]
Description=Conduit frontend
After=network.target conduit.service

[Service]
User=conduit
WorkingDirectory=/opt/conduit/src/frontend
EnvironmentFile=/etc/conduit/web.env
ExecStart=/usr/bin/node server.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

`deploy/Caddyfile.j2` — the web server from Lesson 4:

```text
{{ site_name }} {
	reverse_proxy 127.0.0.1:3000
}
```

**5. The playbook.** Create `deploy/playbook.yml`. You may copy it; then read every block with the instructor and name the mission of Lesson 3 or 4 that it replaces. Spaces, not tabs.

```yaml
- name: Set up the Conduit server and release one commit
  hosts: conduit
  become: true
  vars:
    revision: main

  tasks:
    # ---- what Lesson 3, Mission 2 installed by hand ----
    - name: Install the system packages
      ansible.builtin.apt:
        name: [git, acl, python3-venv, python3-packaging, python3-psycopg2, postgresql, caddy]
        update_cache: true
        cache_valid_time: 3600

    - name: Download the Node.js installer
      ansible.builtin.get_url:
        url: https://deb.nodesource.com/setup_22.x
        dest: /root/nodesource_setup.sh
        mode: "0700"

    - name: Add the Node.js package source
      ansible.builtin.command: bash /root/nodesource_setup.sh
      args:
        creates: /etc/apt/sources.list.d/nodesource.sources

    - name: Install Node.js
      ansible.builtin.apt:
        name: nodejs

    # ---- Lesson 3, Mission 3: a small user and locked secrets ----
    - name: Create a user that can only run the application
      ansible.builtin.user:
        name: conduit
        system: true
        shell: /usr/sbin/nologin
        create_home: false

    - name: Create the folder for the secrets
      ansible.builtin.file:
        path: /etc/conduit
        state: directory
        mode: "0700"

    - name: Create the API secrets once and never overwrite them
      ansible.builtin.copy:
        dest: /etc/conduit/conduit.env
        force: false
        mode: "0600"
        content: |
          APP_ENV=prod
          SECRET_KEY={{ lookup('ansible.builtin.password', '/dev/null', length=48, chars=['ascii_letters', 'digits']) }}
          JWT_SECRET_KEY={{ lookup('ansible.builtin.password', '/dev/null', length=48, chars=['ascii_letters', 'digits']) }}
          POSTGRES_HOST=127.0.0.1
          POSTGRES_PORT=5432
          POSTGRES_DB=conduit
          POSTGRES_USER=conduit
          POSTGRES_PASSWORD={{ lookup('ansible.builtin.password', '/dev/null', length=32, chars=['ascii_letters', 'digits']) }}
      no_log: true

    - name: Create the frontend secrets once and never overwrite them
      ansible.builtin.copy:
        dest: /etc/conduit/web.env
        force: false
        mode: "0600"
        content: |
          PORT=3000
          REACT_PUBLIC_API_ENDPOINT=http://127.0.0.1:8000/api
          SESSION_SECRET={{ lookup('ansible.builtin.password', '/dev/null', length=48, chars=['ascii_letters', 'digits']) }}
      no_log: true

    - name: Read the database password back from the server
      ansible.builtin.slurp:
        src: /etc/conduit/conduit.env
      register: secrets
      no_log: true

    - name: Create the database user
      community.postgresql.postgresql_user:
        name: conduit
        password: "{{ secrets.content | b64decode | regex_search('POSTGRES_PASSWORD=(.+)', '\\1') | first }}"
      become_user: postgres
      no_log: true

    - name: Create the database
      community.postgresql.postgresql_db:
        name: conduit
        owner: conduit
      become_user: postgres

    # ---- the release: code, libraries, build ----
    - name: Get the code of one exact commit
      ansible.builtin.git:
        repo: "{{ repo_url }}"
        dest: /opt/conduit/src
        version: "{{ revision }}"
        force: true
      register: code
      notify:
        - Restart the API
        - Restart the frontend

    - name: Install the Python libraries
      ansible.builtin.pip:
        requirements: /opt/conduit/src/backend/requirements.txt
        virtualenv: /opt/conduit/venv
        virtualenv_command: python3 -m venv
      notify: Restart the API

    - name: Install the frontend libraries
      ansible.builtin.command: npm install --no-package-lock
      args:
        chdir: /opt/conduit/src/frontend
      when: code.changed

    - name: Build the frontend
      ansible.builtin.command: npm run build
      args:
        chdir: /opt/conduit/src/frontend
      when: code.changed

    # ---- the services and the web server ----
    - name: Install the API service
      ansible.builtin.template:
        src: conduit.service.j2
        dest: /etc/systemd/system/conduit.service
        mode: "0644"
      notify: Restart the API

    - name: Install the frontend service
      ansible.builtin.template:
        src: conduit-web.service.j2
        dest: /etc/systemd/system/conduit-web.service
        mode: "0644"
      notify: Restart the frontend

    - name: Configure the web server
      ansible.builtin.template:
        src: Caddyfile.j2
        dest: /etc/caddy/Caddyfile
        mode: "0644"
      notify: Reload the web server

    - name: Start everything now and after every reboot
      ansible.builtin.systemd_service:
        name: "{{ item }}"
        state: started
        enabled: true
        daemon_reload: true
      loop: [conduit, conduit-web, caddy]

    - name: Apply restarts now if anything changed
      ansible.builtin.meta: flush_handlers

    # ---- the check ----
    - name: Check that the API answers
      ansible.builtin.uri:
        url: http://127.0.0.1:8000/api/health-check
      register: health
      retries: 30
      delay: 1
      until: health.status == 200

    - name: Check that the frontend answers
      ansible.builtin.uri:
        url: http://127.0.0.1:3000/
      register: page
      retries: 30
      delay: 1
      until: page.status == 200

    - name: Show the running version
      ansible.builtin.debug:
        msg: "{{ health.json }}"

  handlers:
    - name: Restart the API
      ansible.builtin.systemd_service:
        name: conduit
        state: restarted
        daemon_reload: true

    - name: Restart the frontend
      ansible.builtin.systemd_service:
        name: conduit-web
        state: restarted
        daemon_reload: true

    - name: Reload the web server
      ansible.builtin.systemd_service:
        name: caddy
        state: reloaded
```

> [!NOTE]
> Every task describes a result: this package is installed, this user exists, this file has this content. Before doing anything, Ansible looks at the server. If the result is already there, it reports `ok` and moves on. That property is called **idempotent**.

> [!NOTE]
> `force: false` means: create the file only if it is missing. On your server the secrets from Lessons 3 and 4 already exist, so they are kept. On a new server they are generated there. They are never in Git and never on your laptop, and `no_log` keeps them out of the output.

**6. Commit and push the branch**, so the server can download it:

```bash
git add deploy/
git commit -m "Describe the whole server as an Ansible playbook"
git push -u origin deploy/ansible
```

**7. Run it against the server you built by hand:**

```bash
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml -e revision=deploy/ansible
```

It takes a minute or two. Checkpoint: the summary line ends with `failed=0`. Only a few tasks say `changed`; most say `ok`, because you already did that work by hand. The last task shows a `revision` that equals `git rev-parse HEAD`.

**8. Run it again:**

```bash
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml -e revision=deploy/ansible
```

Checkpoint: `changed=0`. Nothing was installed, built or restarted, and your site stayed up.

**9. Merge.** Open a pull request into your own fork and merge it. Your server is now described by code that went through review.

## Mission 5 · Release and roll back (20 minutes)

**1. Version 0.4.0.** On a new branch change `0.3.1` to `0.4.0` in `backend/version.py`, open a pull request into your own fork and merge it:

```bash
git switch main
git pull
git switch -c release/0.4.0
```

```bash
git add backend/version.py
git commit -m "Release 0.4.0"
git push -u origin release/0.4.0
```

**2. Release it:**

```bash
git switch main
git pull
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml
```

Checkpoint: the last task shows `"version": "0.4.0"` and a `revision` equal to `git rev-parse HEAD`.

**3. Roll back** to the commit before it, with the same command:

```bash
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml -e revision=$(git rev-parse HEAD~1)
```

Checkpoint: `"version": "0.3.1"`, and the revision of the older commit.

**4. Go forward again:**

```bash
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml
```

> [!NOTE]
> In Lesson 3 you had to log in and ask Git which commit was on the server. Now the running application says it itself. When something breaks at night, the first question is always “which version is this?”, and the answer is one request away.

## Bonus (if you finish early)

**A. A second server from nothing.** In Cloud Shell, create a second server in its own resource group, in the same region as the first:

```bash
az group create --name devsecops-2 --location <your region>
az vm create --resource-group devsecops-2 --name conduit-server-2 --image Ubuntu2404 \
  --size Standard_B2ats_v2 --admin-username azureuser --ssh-key-values "<your public key>" --public-ip-sku Standard
az vm open-port --resource-group devsecops-2 --name conduit-server-2 --port 80 --priority 1020
```

Add a second line under `[conduit]` in `deploy/inventory.ini`. It has no domain name, so it serves plain HTTP:

```ini
server2 ansible_host=SECOND-IP ansible_user=azureuser site_name=:80
```

Add its host key and run the playbook only for it:

```bash
ssh-keyscan -t ed25519 SECOND-IP >> deploy/known_hosts
ansible-playbook -i deploy/inventory.ini deploy/playbook.yml --limit server2
```

Checkpoint: about four minutes later `http://SECOND-IP` shows Conduit. Then delete the second server, so it does not use your credit: `az group delete --name devsecops-2`. Do not commit the second line of the inventory.

## Troubleshooting

1. **The script stops with `Permission denied`.** The command needs `sudo`: `ssh azureuser@YOUR-IP 'sudo bash -s' < scripts/release.sh`.
2. **The script prints `curl: (22)` and no `OK`.** The release is broken: the API answered with an error. Read `sudo journalctl -u conduit -n 30 --no-pager` on the server.
3. **Ansible: `Host key verification failed`.** `deploy/known_hosts` is missing or belongs to another address. Repeat Mission 4, step 3, and run Ansible from the repository folder.
4. **Ansible: `couldn't resolve module/action 'community.postgresql…'`.** Run `ansible-galaxy collection install community.postgresql`.
5. **Ansible: a task fails with a YAML or indentation error.** Compare the playbook with the lesson line by line; spaces, not tabs.
6. **`Get the code of one exact commit` fails.** The branch or commit is not on GitHub yet (push it), or `repo_url` in the inventory is wrong.
7. **The health check task fails after 30 retries.** On the server: `sudo journalctl -u conduit -n 30 --no-pager`.
8. **`ansible-playbook: command not found`.** The Python environment is not active: `source .venv/bin/activate`.
